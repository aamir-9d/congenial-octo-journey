# Implementation plans

One file per piece of work, named `<what>-plan.md`. A plan records the problem,
the approach and why it beat the alternatives, the phases, how each was
verified, and what is still not known. Rejected options stay in the file on
purpose, so nobody proposes them again without the reason in front of them.

The first line under the title is a bold **Status** line. Update it when a
phase lands; do not delete what came before.

What happened in a session goes in `changelog/`. What a plan decided goes here.

**This repository is public.** No personal email addresses, account names,
keys, client names, prices or anything confidential in a plan.
